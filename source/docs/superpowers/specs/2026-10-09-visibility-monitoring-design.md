# 可见性监测页面设计

## 目标

完成新人引导后，用户进入独立的「可见性监测」结果页面。该页面沿用现有 GEO 工作台布局和侧边栏，并覆盖用户提供截图中的监测概览、可信度、品牌与竞品分析、问答命中、信源域名追踪及相关详情交互。

## 已确认的产品流程

- 新人引导是独立页面，不显示工作台侧边栏。
- 最后一步按钮「开始首次监测」完成引导并导航到新页面「可见性监测」，不再只显示完成 toast。
- 可见性监测页面复用 `GeoWorkbenchLayout` 外壳；侧边栏增加「可见性监测」导航项。
- 页面使用现有工作台路由体系，直接访问结果页时仍遵守 onboarding 完成状态守卫。

## 页面范围

### 监测概览与采样可信度

- 页面标题下方固定显示「本轮监测」摘要卡，包含日期、市场/语言、人设、意图、关键词、监测问题、AI 平台和采样可信度，并可从「监测规则」入口进入采样配置阶段。
- 使用可点击的五阶段流程导航：品牌知识、买家人设、监测问题、采样执行、监测结果。阶段导航点击后只显示当前阶段内容，不把不同截图的阶段面板堆叠在同一页面。
- 品牌知识、买家人设、监测问题阶段各自显示对应配置内容；采样执行阶段显示可信度和口径规则；监测结果阶段再显示品牌分析、问答命中和信源域名三个结果子页。
- 显示当前监测流程摘要、市场/语言、监测问题数、平台数、采样周期和最近一轮状态。
- 显示趋势级/决策级可信度视图切换、累计采样区间、样本量、有效返回率、双源一致率、人工复核一致率、置信区间、复现波动及引擎漂移告警。
- 展示采样节奏、人设层置信区间、IAB 测量原则，以及采样口径与判定规则说明。
- 支持打开采集频率与 AI 平台配置弹窗；频率、日期/时间和可用平台按截图提供选项，保存后更新页面演示状态。Claude 等截图中标记暂不开放的平台保持禁用。

### 品牌提及分析

- 页面内结果标签包含「品牌提及分析」「问答命中明细」「信源域名追踪」。
- 品牌提及分析包含 12 周趋势图和筛选：整体+置信区间、按引擎、按人设、品牌 vs 竞品。
- 提供我方及竞品表现卡片、买家人设 × 核心主题热力图、买家人设 × 购买意图/阶段热力图。
- 竞品集合及我方品牌以当前演示数据呈现；未确认品牌不作为正式竞品参与比较。

### 问答命中明细与问题详情

- 表格展示监测问题、AI 平台提及情况、是否提及竞品、是否引用官网、排名/趋势及查看详情入口。
- 问题详情面板展示综合表现、采样批次与样本量/置信区间、品牌提及和引用表现、引用页面、提及趋势及逐平台回答明细。
- 切换采样批次和展开回答可查看对应的演示记录；点击引用页面可打开对应来源详情。

### 信源域名追踪与来源详情

- 展示来源域名的命中问题数、引用次数、引用平台、我方是否提及和是否被竞品引用。
- 展示被引页面标题、来源域名、命中问题、引用平台及引用摘要。
- 域名或页面详情入口打开详情面板，呈现关联引用和问题信息。

## 交互与数据

- 所有统计图表使用 ECharts；图表筛选切换对应演示序列，悬停可查看数据。ECharts 只用于统计图表，普通界面图标继续使用项目现有组件。
- 表格标签、筛选、批次、折叠内容、提示说明、标签页、详情面板和配置弹窗均按截图提供可操作状态。
- 目前仓库没有可见性监测 API 或对应的服务端数据契约；首版通过类型化的本地演示数据实现页面，不虚构后端请求。后续接入 API 时保留页面组件边界并替换数据来源。
- 演示数据集中管理，页面组件通过明确的 props/事件或 composable 获取数据和更新筛选状态，不在图表组件内部持有业务数据。

## 技术结构

```text
src/
  views/VisibilityMonitoringView.vue       # 可见性监测路由视图
  components/pages/visibility-monitoring/  # 仅属于「可见性监测」页面的区块组件
  data/visibility-monitoring-data.ts        # 本地演示数据与类型
  components/GeoSidebar.vue                 # 工作台入口
  layouts/GeoWorkbenchLayout.vue            # 共享外壳
  router/index.ts                           # 路由与引导守卫
```

沿用当前 Vue 3 `<script setup lang="ts">`、Vue Router、Pinia 和 CE 组件约定。ECharts 图表采用按需注册的 `echarts/core` 与 SVG renderer，按现有 `GeoRadarChart` 的生命周期模式初始化、监听尺寸并在卸载时 dispose。

页面专属组件必须放在 `src/components/pages/<page-name>/`；本功能使用 `src/components/pages/visibility-monitoring/`。跨页面复用的通用组件继续放在 `src/components/` 或 `src/components/ui/ce/`，本次不搬迁既有组件。

## 视觉规范

- 参考 `/Users/zhangaichen/Downloads/外部对接样式/external-iframe-style-guide.md` 的语义颜色、文字层级、空间节奏、圆角、边框、控件状态和响应式要求；使用项目已有 CSS tokens/CE 组件，避免另建平行视觉系统。
- 本项目当前技术栈优先：Vue 3、现有 CE 组件、ECharts。规范附件中的 React、shadcn 和 Recharts 只描述该规范原始项目，不作为本项目依赖要求。
- 内容宽度随工作台可用区域伸缩，不新增固定最大宽度；页面仅保留最外层纵向滚动条，长表格局部横向滚动，业务数据列表不默认增加外框与阴影。
- 沿用规范字号层级与语义色：页面标题20px、区块标题16px、正文14px、辅助文字12px；避免将正文和指标标签放大。普通内容卡片采用1px边框、12px圆角、16px内边距；页面模块间保持16px节奏，不能让相邻主卡片贴边。窄屏时左右页边距16px（可用宽≤760px）、卡片内边距16px（≤520px），两列布局≤760px转单列。
- 验证320px窄内容区和200%缩放下内容、焦点、状态及操作仍可用；不改变现有工作台外壳或全局主题。

## 命令与验证

- 构建与类型检查：`npm run build`
- 测试：`npm test`
- 静态检查：`npm run lint`
- 浏览器验收：从新人引导末步进入可见性监测；检查侧栏激活态、三个结果标签、筛选交互、图表、配置弹窗、问题/来源详情及直接访问路由守卫。

## 范围边界

- 必须：实现全部截图覆盖的页面区块及主要可见交互；新人引导继续无侧栏；结果页沿用现有工作台；统计图表使用 ECharts；保留现有路由和功能。
- 首版不做：真实监测采集、后端 API/持久化、账号权限、真实采样调度及真实统计计算。截图数字作为演示数据，不宣称为实时结果。
- 不做：替换整个工作台导航/布局、重构无关 GEO 模块、引入新的图表库。

## 验收标准

1. 新人引导流程不出现左侧工作台导航。
2. 完成最后一步后，路由进入名为「可见性监测」的新页面，现有工作台侧栏显示并选中「可见性监测」。
3. 页面显示本轮监测摘要卡；五阶段导航可点击切换且同一时刻只展示所选阶段面板，结果阶段内再切换品牌趋势与对比、两类热力图、问答命中表与问题详情、来源域名/页面追踪与详情；采样执行阶段包含可信度、频率/平台配置弹窗及采样规则说明。
4. 所有统计图表均以 ECharts 渲染；筛选和标签切换有对应的可见状态变化。
5. 页面数据由本地演示数据提供，不产生未经支持的 API 请求。
6. 新旧路由均可正常访问；视觉遵循附件的语义 token、空间/文字层级、单一纵向滚动和局部横向表格滚动，并通过320px与200%缩放验收。
7. `npm run build`、`npm test`、`npm run lint` 通过，浏览器验收流程通过。

## 待确认假设

- 首版以截图中的示例品牌、指标、问题、平台和域名作为本地演示数据；无需接入真实监测 API。
- 页面需覆盖截图中展示的内容与主要交互，不要求复刻截图之外的采集后端或统计计算。
