# 纯前端 Mock 项目设计

## 目标

在当前工作区创建独立的 `geo-agent-web-mock/` 项目，复制现有 Vue 应用并将所有后端行为替换为本地假数据，使演示只需启动前端即可运行。原项目和原页面保持不变。

## 已确认约束

- 原项目页面和源代码不参与此次实现；所有应用改造只在 `geo-agent-web-mock/` 副本内进行。
- 保留现有页面、路由、布局、组件结构、文案和样式；只有为无后端流程补足必要交互时才改行为。
- 不需要 API 凭证、iframe 宿主或后端服务。
- 用户修改保存在浏览器 `localStorage`，刷新后仍保留；说明如何恢复初始演示数据。
- Mock 加载只使用简短的现有视觉反馈，不显示“正在读取后端”等提示。
- 手动维护的竞品与 AI 推荐候选分开保存。按规范化名称、别名或域名过滤已经维护的竞品；确认候选后将其移入手动竞品列表，并从推荐列表移除。

## 项目复制范围

将应用源码、测试、静态资源、Vite/TypeScript/lint 配置和 package 元数据复制到 `geo-agent-web-mock/`。不复制 `.git`、`node_modules`、`dist`、编辑器状态或真实环境文件。副本采用安全的本地演示默认配置，不配置真实 API 地址。副本是可以独立安装依赖的前端项目；开发时可临时复用现有依赖目录以节省安装时间。

## Mock 架构

在副本中增加本地 mock 数据与服务层。版本化 localStorage 仓库负责初始化种子数据、读取和持久化修改。Mock 服务通过本地仓库提供异步操作，并模拟确定、短暂的延迟，但不发送网络请求。保留对 UI 有用的 TypeScript 数据契约；从副本启动流程中移除 Axios 客户端、API 代理配置、委托认证和宿主桥接。

种子数据覆盖现有主要页面：总览、引导与市场配置、可见性监测设置及采集/结果、竞品推荐、诊断与优化、报告列表/生成/详情、任务详情。页面操作应更新跨页面共享的本地状态，使配置修改能影响监测与报告，新生成或审核的数据出现在相应列表。

## 流程行为

- 配置表单可新增、编辑、删除、保存、校验和完成。
- 监测可保存计划、暂停/恢复、手动采集，并更新轮次与结果视图。
- AI 推荐支持生成、接受和忽略；已接受的竞品进入手动维护列表且不重复。
- 报告操作支持生成最新报告、筛选和选择报告、查看本地种子或新生成的报告详情。
- 诊断、优化和任务操作更新本地状态，以便演示进度和完成状态。
- 现有加载、空和错误状态应可由 mock 返回驱动；错误应可预测，只用于无效输入或 mock 数据不存在等情况。

## 验证标准

- 副本可独立构建，相关测试在副本内通过。
- 确认副本没有运行时网络请求或 API 主机依赖。
- 验证代表性流程：修改并保存配置、接受不重复的 AI 竞品、启动/暂停/恢复采集、生成并查看报告。
- 验证本地修改刷新后仍保留，并说明重置方法。
- 在相同视口对照原项目，确认副本视觉样式没有变化。

## 范围边界

这是用于演示的纯前端项目，不实现替代后端、多用户同步或本地演示数据的生产级安全。季度报告仍可以作为报告类型展示；mock 层只模拟产品现有流程，不改造报告周期规则。
