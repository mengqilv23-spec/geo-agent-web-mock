# 概览页面设计

## 目标

新增一个带全局左侧菜单入口的「概览」页面，将当前监测轮次、核心 GEO 指标、AI 平台表现与 Agent 待处理事项集中呈现，便于用户快速判断整体情况并进入对应业务模块。页面结构以用户提供的三张截图为参考，视觉沿用 GEO 工作台。

## 页面入口与范围

- 在现有全局侧栏最上方新增「概览」入口，注册独立 `/overview` 路由，并正确显示活动态。
- 根路径 `/` 继续重定向到「诊断与策略」，不改变现有默认进入行为。
- 页面复用当前可见性监测和工作台中的演示数据及任务状态；不新增后端接口、独立导航、持久化或权限流程。
- 页面内跳转进入现有可见性监测、诊断与策略、优化中心及任务详情，不复制这些模块的业务详情。

## 页面内容

### 页面标题与本轮监测

- 页面标题为「概览」，配简洁的信息提示入口。
- 「本轮监测」摘要卡显示运行状态与暂停/开启交互，以及监测日期、市场/语言、买家人设、意图、关键词、监测问题、AI 平台数和采样可信度。
- 状态操作只更新当前页面的本地演示状态，不实际启动或停止服务。

### 核心指标概览

- 展示品牌提及率（SOA）、品牌推荐率、官网引用率和声量份额（SOV）四项指标卡；呈现本轮值以及与上次监测/基线的对比。
- 指标趋势图展示最近 7 个采样周期，并提供与图例一致的多指标序列。
- 图表下方展示平均位次和回答事实准确率摘要。
- 复用现有监测数据模型。现有数据未覆盖的历史对比、SOV 或事实准确率字段，统一放在明确标注的演示数据中，不将推算值描述为真实业务结果。

### 各 AI 平台表现

- 按平台列出提及率、官网引用率的可视化条、样本量及周期变化；平台数据来自现有引擎趋势和监测问题结果。
- 提供进入可见性监测页查看完整数据的入口。
- 无有效样本的平台显示空状态，不以虚构数值填充。

### Agent 工作队列

- 聚合工作台提供的待处理诊断、候选策略与任务，显示待处理数量、优先级、来源、状态、摘要和下一步。
- 支持按优先级/来源筛选；操作跳转到已有诊断、优化中心或任务详情流程。
- 队列仅作聚合与导航，不在概览页重复创建确认、审核或发布操作。

## 数据与组件边界

- 新增独立概览视图及聚焦页面展示的组件；路由和导航按现有模式接入。
- 监测摘要、平台指标、趋势与样本数据读取 `visibility-monitoring-data`；待办从工作台路由上下文的 findings、strategies、tasks 派生。
- 以计算属性从共享来源派生数量和状态；页面筛选/暂停状态仅在本地，不改变源业务记录。
- 图表优先复用现有监测图表实现；概览专属卡片和列表不改写监测分析页面。

## 视觉、响应式与可访问性

- 使用现有侧栏、页面容器、设计 token、卡片、状态色与字体规范；保持内容区节奏紧凑，层级清楚。
- 桌面端按截图组织为纵向分区；中小屏将指标卡、平台表现与工作队列合理改为单列/纵向布局，避免页面级横向溢出。
- 趋势图需有可读图例、日期标签与文本替代说明；颜色不是区分数据的唯一手段。
- 信息提示、监测开关、筛选和跳转均使用语义化交互控件，支持键盘与可见焦点。

## 验收标准

1. 左侧菜单出现「概览」并能进入 `/overview`；直接访问和刷新路由正常，活动菜单状态正确。
2. 页面具备监测摘要、四项核心指标及趋势、平均位次/事实准确率、AI 平台表现和 Agent 工作队列分区。
3. 当前监测数据和工作台待办与源数据一致；演示补充值有明确的数据边界，不伪装为实时业务数据。
4. 暂停/开启、优先级/来源筛选及模块跳转均可操作，且不会改变后端或越权修改业务状态。
5. 桌面与窄屏布局可读、无页面级横向溢出；相关组件测试、类型检查、lint 与构建通过。

## 明确不做

- 不把概览改为应用默认首页。
- 不新增后端 API、采样/监测控制、数据持久化或权限系统。
- 不在概览页重新实现完整的监测分析、诊断、审核、优化和任务详情。
- 不将截图里的演示数字当成现有系统真实数据。
