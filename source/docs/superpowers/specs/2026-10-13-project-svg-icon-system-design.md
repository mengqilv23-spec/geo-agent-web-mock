# 全站 SVG 图标统一设计

## 目标

统一 GEO Agent Web 全站界面图标的视觉语言与实现方式，修复当前 IconFont、symbol SVG、手写 SVG 和字符图标混用导致的线条、尺寸和颜色不一致。目标是让导航、操作、提示和状态图标统一、清晰、可访问，同时避免引入整套图标资源造成不必要的包体积增长。

## 当前情况

- `package.json` 当前没有图标库依赖。
- `src/components/ui/ce/icon-font/IconFont.vue` 提供 IconFont 包装，但仓库中没有发现对应的字体文件或 `@font-face` 定义；CE 组件仍在通过 `iconType` 使用若干旧名称。
- `src/components/ui/ce/svg-icon/SvgIcon.vue` 通过 `<use href="#...">` 引用 SVG symbol，但仓库内没有找到对应的 symbol sprite，且当前应用没有实际使用该组件。
- 项目另有手写 SVG，以及用于上传、状态、导航和反馈的字符符号。
- README 表明 UI 组件用于嵌入其他项目，因此 CE 组件导出和既有 `iconType` props 可能构成外部接口，需要避免无计划地破坏。

## 方案

采用 Lucide 的 Vue SVG 组件，官方当前 Vue 包名为 `@lucide/vue`。仅通过命名导入实际使用的图标，禁止使用导入整个图标命名空间的方式。

新增统一 `AppIcon` 入口与静态语义图标表：

- 对外以项目语义名称表达图标用途，不在页面重复引用图标库内部命名。
- 统一默认尺寸、`strokeWidth` 与 `currentColor`；允许少数明确场景覆盖尺寸。
- 装饰图标默认对辅助技术隐藏；没有可见文字且图标承担操作名称时，调用方提供无障碍名称。
- 只映射实际用到的图标，确保按需打包并能从映射中审查全站图标语义。

建议默认使用 18px 图标、约 2px 描边，具体尺寸继续服从现有 CE 控件尺寸 token；颜色继承文字或控件语义色，不在图标组件中引入另一套调色板。

## 范围

纳入统一：

- 全站导航、返回/前进、展开/收起、关闭、新增、搜索等控件图标。
- 按钮、表单、上传区域、提示/弹窗、流程节点、状态和趋势等界面图标。
- 替换旧 IconFont 在仓库内的调用，并清点纯展示用途的手写 SVG 与字符图标。

保留原样：

- 国家/地区旗帜、品牌标志和产品专属插画。
- ECharts 或自定义图表中的数据图形、坐标、曲线和装饰性数据标记。
- 正文、用户内容、算式及流程说明文案中的箭头、乘号等文本符号。
- 有明确数字含义的步骤序号及其他非图标数据。

## 兼容性

迁移前枚举 CE 组件的导出、`iconType` 参数和已知旧图标名称。应用内部统一改用 `AppIcon`；对组件库可能被外部消费的导出和 props，保留现有形状，并将已知旧名称映射至 SVG 图标。若某名称没有等价图标，不静默显示错误图形，应保留兼容 fallback 并给出开发期诊断。

现有 `SvgIcon` 是已导出的组件，即使仓库内无调用，也先保留兼容；本次不删除公共导出、不改变无关组件 API。旧 IconFont 如无外部真实字体依赖，可内部转为兼容适配层，后续再单独决定移除时机。

## 迁移步骤

1. 添加并锁定 `@lucide/vue` 依赖，建立有穷、静态、按需导入的语义图标表和 `AppIcon`。
2. 迁移 CE 公共组件（按钮、Alert、MessageModal、内容预览）及共享导航/控件，保持其 props 与外观语义兼容。
3. 按功能域迁移任务工作区、优化/诊断、概览/报告、引导流程、可见性监测等页面中的界面图标。
4. 清点字符符号与内联 SVG，按上述范围替换；保留品牌、旗帜、图表和文本符号。
5. 检查没有遗留的应用内 IconFont 调用或未使用映射，并确认兼容导出仍可正常工作。

迁移按组件/功能域分批进行，每批先验证测试和页面外观，不做与图标无关的重构。

## 验收标准

- 全站界面图标采用一致的 SVG 线性风格、尺寸层级、描边和语义颜色。
- 操作/状态含义清晰；装饰图标不重复朗读，纯图标按钮仍有可访问名称。
- 国旗、品牌标志、图表数据图形、正文符号与数字步骤保持原语义。
- 不使用整库 wildcard 导入；生产构建只包含静态映射中实际使用的图标。
- 既有 UI 组件导出和 `iconType` props 不发生未经确认的破坏性变更。
- 单元/组件测试、lint、TypeScript 与生产构建通过；在主要页面及窄屏视口做视觉回归。
- 记录迁移前后主要 JS/CSS 产物体积，确认增量来自实际使用的图标且无整库加载。

## 主要风险

- 同一 Unicode 字符目前可能在不同页面表达不同语义；迁移时以页面功能判断，不做机械替换。
- 外部嵌入方可能使用 CE 导出的旧 IconFont 或 `iconType`；通过兼容适配和 API 测试降低破坏风险。
- 图标增量取决于实际使用数量；以静态导入和构建产物对比验证，不预先假设固定体积。
