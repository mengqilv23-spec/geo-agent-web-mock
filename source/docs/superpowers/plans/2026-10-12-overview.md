# 概览页面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 GEO 工作台新增带左侧菜单入口的概览页，汇总监测指标、平台表现与可跳转的 Agent 待办。

**Architecture:** 新增 `/overview` 子路由和独立页面，将「概览」放在现有侧栏首项，但保留 `/` 当前重定向。页面通过路由上下文读取 findings、strategies、tasks，通过可见性监测数据展示摘要/趋势/平台表现；页面专属的视图模型与展示组件保持独立。

**Tech Stack:** Vue 3 `<script setup lang="ts">`, Vue Router 4, Pinia 路由上下文, ECharts 6, Vitest, Vue Test Utils, ESLint, vue-tsc, Vite。

**Spec:** `docs/superpowers/specs/2026-10-12-overview-design.md`

## Global Constraints

- 根路径 `/` 继续重定向到「诊断与策略」，不改变现有默认进入行为。
- 页面复用当前可见性监测和工作台中的演示数据及任务状态；不新增后端接口、独立导航、持久化或权限流程。
- 状态操作只更新当前页面的本地演示状态，不实际启动或停止服务。
- 页面内跳转进入现有可见性监测、诊断与策略、优化中心及任务详情，不复制这些模块的业务详情。
- 现有数据未覆盖的历史对比、SOV 或事实准确率字段，统一放在明确标注的演示数据中，不将推算值描述为真实业务结果。
- 无有效样本的平台显示空状态，不以虚构数值填充。
- 队列仅作聚合与导航，不在概览页重复创建确认、审核或发布操作。
- 中小屏避免页面级横向溢出；颜色不是区分图表数据的唯一手段。

## Review Focus

- 直接访问或刷新 `/overview` 时工作台上下文必须存在，导航活动态正确；由路由集成测试覆盖。
- “待处理”筛选必须只纳入真实待处理 finding、未确认且未忽略策略、以及可操作阶段任务；由聚合视图模型测试覆盖。
- 空的平台结果和空的队列筛选都必须有明确空态；由视图组件测试覆盖。
- 暂停/开启监测只是页面内演示状态，不得修改共享数据或触发业务执行；由页面交互测试覆盖。
- 切换至任务详情/来源模块时必须使用现有上下文回调或已注册路由，不可产生悬空链接；由队列跳转测试覆盖。
